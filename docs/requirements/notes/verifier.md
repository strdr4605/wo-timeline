## Findings for the orchestrator (no item fails because of them)

1. `measure.mjs` marks an item `fail` when any single measurement for that id fails. G5 holds a
   measurement for `.drawer__title`, a wave 3 element, so a bare `measure.mjs` run reports
   "FAIL G5: selector not found: .drawer__title" and overwrites the pass that `verify.mjs` wrote.
   The file currently reads pass because verify ran last. Run order matters and the harness does
   not say so.
2. C3, C4, C5 and G4 are `fail` in the file only because their elements belong to waves 2 and 3.
   The file will show four fails until the bars and the drawer land.
3. `docs/design/tokens.json` is a source of truth and the builder added six values to it in
   wave 1. Four are measurable from the Sketch dump, two are the Q15 agent choices. If the token
   file must stay a pure Sketch extraction, the four measured values belong in the file anyway, but
   the file needs a note that says which entries are agent choices.
4. The local font fallback contradicts decision Q13 and Q19. Either the decision record or the
   README deferral list has to change, not both.
5. B6 and B9 deviate from the artboard in ways a human reviewer will see: the current month pill
   reads "Nov 2026" instead of "Current month" and is 76.89 wide instead of 109, and the work
   centre row and the timeline row do not share one hover.
6. The chip is 2px wider than the Sketch because the 1px border of `components.scaleChip.border`
   sits outside the 75 + 71 segments.
